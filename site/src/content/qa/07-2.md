<strong>假設情境 · 英文：</strong>

<details class="original-question">
<summary>English · hypothetical scenario</summary>
<blockquote lang="en">Suppose a project searches libraries and museums for a category of materials. Can specific instructions ensure completeness, and how should coverage and gaps be recorded?</blockquote>
</details>

具體指令能改善搜尋，但不能保證找齊所有圖書館與博物館資料，也不能增加原本沒有的存取權限。

先界定時段、地域、媒介、異名和核心機構。讓 AI 協助產生多語檢索詞，分別查學術索引、機構原生目錄及參考書目；保留檢索式、日期、館藏號與原始連結，並去除重複。

請分開記錄：<strong>找到目錄、看得到影像、取得全文、實際讀過</strong>。用已知作品測試搜尋是否會漏，並到重要機構的原生目錄回查。零結果只代表這次查詢沒找到。

成果應該是有範圍、能回查、列明缺口的資料清單，而不是「全部找齊」的保證。Workshop 會示範如何讓 agent 執行這樣的搜尋計畫。

實作的難處是，多數圖書館／博物館系統仍是為人設計，未必有 agent-friendly 的 API。可先用官方介面；只有網頁時，讓 agent 在你平日使用、已登入的 <strong>Chrome／Edge browser profile</strong> 中協作。校園 VPN、登入或 CAPTCHA 由你處理，再交回 agent 繼續；每個庫的流程不同，不能期待一個腳本通吃。

每摸清一個資料庫，就積累一份專屬 Skill。我用過的一個例子是<strong>讀秀（Duxiu）</strong>：有段時間頁面沒有年代篩選側欄，但 URL 的 query parameters 仍可限定起迄年份。發現後把當時有效的參數規則記進檢索 Skill，下次便不用重找。這是說明如何記錄實際觀察的竅門，並不是在此保證某組未核實的參數今天仍適用。

實際清單還可把狀態細分為「只見題名 → 已讀館目 → 已見清晰圖 → 已取得全文／高解析圖 → 已細讀核查」。當異名查詢和參考文獻追索開始反覆指向同一批核心材料，就收口進入細讀，同時列出仍受存取或未數位化限制的缺口。
