<strong>假設情境 · 英文：</strong>

<details class="original-question">
<summary>English · hypothetical scenario</summary>
<blockquote lang="en">Suppose a project studies historical images. How could multimodal models, visual features and OCR be compared to choose suitable methods?</blockquote>
</details>

假設有上述研究情境，可以從以下方法開始。

先按任務選方法：

- <strong>看圖並追問細節</strong>：多模態語言模型方便建立初步描述，但必須區分可見內容與歷史推論，細小線刻及古文字要回原圖核對。
- <strong>文字找圖／以圖找圖</strong>：CLIP、SigLIP 等可用於圖文檢索；DINOv2 等視覺特徵可用於相似圖像檢索。它們提供候選排序，不能直接證明題材、年代或象徵。[CLIP 論文](https://arxiv.org/abs/2103.00020)、[SigLIP 論文](https://arxiv.org/abs/2303.15343)、[DINOv2 論文](https://arxiv.org/abs/2304.07193)。
- <strong>讀題字／定位局部</strong>：分別考慮 OCR 或物件定位方法；讀出文字、圈出動物與解釋作品是不同工作。

對這類假設圖集，先拿一小組包含正例、反例和困難頁的材料比較，記錄漏檢、誤報及核對時間；整頁與裁切局部也要分別試。不要只比較模型自稱的信心或通用排行榜。Workshop 會示範怎樣設計這個小試驗，而非要求大家訓練一個模型。

課前準備的同一個 OpenRouter API key 可呼叫多模態視覺 LLM 與 embeddings，由自己的 coding agent（OpenCode／Claude Code／Codex）安排頁面／局部描述、相似檢索與聚類；圖像輸入須選支援該能力的 embedding 模型。

我會再分開兩種能力：<strong>純粹看見／讀出圖上東西的能力</strong>，以及<strong>動用世界知識、理解人文語境和表達細緻解釋的能力</strong>。OCR 測得好，不等於藝術史分析就細膩；反過來，漂亮的藝術史敘述也不證明看清了細節。以我的使用經驗，Claude Opus 與 Gemini 值得拿來做這類人文比較，但這是選擇實測候選的經驗，不是任何題目都固定勝出的榜單。

傳統視覺特徵與多模態 LLM 也不必二選一：大量圖庫可先用特徵或向量排序，小組候選再用詳細描述和原圖細讀。規模、成本、細節和你的研究目的，決定它們如何分工。

一個可做的起點是挑 <strong>20–30 頁</strong>版畫，包含密集建築、山石遮擋、小動物、榜題和不同刻印品質，用同一任務比較 Gemini Flash／Pro 與 Claude Opus 等候選。分別記母題漏檢／誤報、位置描述、文字識讀與語境表述，不用一個總分掩蓋它們的差異。
