<strong>假設情境 · 英文：</strong>

<details class="original-question">
<summary>English · hypothetical scenario</summary>
<blockquote lang="en">Suppose a project needs to compare or identify inscriptions and handwriting in artworks or historical documents. How could AI assist?</blockquote>
</details>

假設有上述研究情境，可以從以下方法開始。

可以先讓 AI 協助產生<strong>待核對的逐行轉寫</strong>。保留原圖，另取清晰題跋區域，標明行序；要求難字留空或列候選，把原字、規範字和解釋分開。核查時返回具體字形，尤其注意人名、年款、印記與漏行。

如果你說的「辨識」還包括書體、書寫者或真偽，就需要另外提供可靠的對照作品及著錄。AI 可以整理可見特徵與差異，候選歸屬則需要更多證據。熟悉的詩句或流暢的補文，不足以證明原圖寫了那些字。

規模也會改變做法。只研究幾件作品時，直接細看可能更有效；若要比較大量題跋，可讓 agent 寫一個小工具，把<strong>不同作品中的同一字、同一段筆畫或同一局部並排放大</strong>，讓你的眼睛先看出規律與差異。

把眼學寫成可討論的規則，也比一開始就訓練小模型實際：例如專家為甚麼覺得 A 與 B 相近、與 C 不同？具體是哪個形狀、起收筆或結體特徵？把可靠對照與理由交給模型，讓它按規則指出圖上位置，再由你判斷。這是在借助模型整理比較，而不是讓一個流暢的鑑定答案代替字形證據。

這類探索可先走「原圖 → 候選轉寫 → 標出疑字 → 核對 → 修訂方法」的小樣本流程；工作坊的 OCR 示範採報紙與一般手稿，不承諾辨識這類高難度字跡。現成視覺模型與專用手寫識別都可作候選；選擇前先測你的字體與圖像，不能用一般 OCR 表現推定題跋準確度。

若希望探索此類題目，可先用自己的 coding agent，透過 OpenRouter API key 對裁切的題跋區域試做視覺模型轉寫，再考慮專門的 HTR；每個候選字仍須回原圖核對。
