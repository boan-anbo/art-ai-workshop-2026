<strong>假設情境 · 英文：</strong>

<details class="original-question">
<summary>English · hypothetical scenario</summary>
<blockquote lang="en">Suppose a project extracts geographic and object information from many archaeological or survey reports. How could processing be divided into chunks while preserving sources?</blockquote>
</details>

假設有上述研究情境，可以從以下方法開始。

可以。先拿幾本版式不同的報告試做，再擴展；不要直接要求模型一次處理全部頁面。

保留原 PDF，讓 OCR／文字提取保留頁碼、表格與圖說。按遺址、器物組或表格分段，附必要上下文。每條候選記錄應包含器物號、原始描述、出土脈絡、數量與單位、年代原說法、地點角色，以及原文定位。

先核對候選表，再納入研究資料。特別檢查正文與圖版的重複、「件／片／標本」混用、漏取及「同上」的跨段關係。空白要分清未記載、不可辨及不適用。

程序穩定後，才把輸入、欄位、頁碼、核查與停止條件寫成 skill，讓 agent 分段執行。Workshop 會示範一頁到可回查表格的完整過程。

規模擴大後，讓 agent 用獨立 API calls 每次讀約 <strong>1–3 頁或 1–3 段</strong>，同時給出整份報告的遺址、年代與必要上下文，不依賴漫長對話的記憶。把原始提取、清理／迭代建模、正式資料庫分開，新增材料時可調整 schema 並遷移。

每條摘錄附頁、行、原句，文字條件允許時留字符定位，以腳本核對引文，再用 Judge 找矛盾。地名先按報告原樣入庫；等資料庫整理好後，才統一做 GIS 映射和歷史地圖對齊。不要在記錄都未清楚時就急着把點畫上地圖。

資料表可先分成<strong>遺址／出土單位表</strong>與<strong>器物表</strong>，用 `site_id`／`unit_id` 連接，免得把每個遺址的地層背景重抄到每件器物。器物保留 `raw_term`，另加你的 `normalized_variety`，讓不同報告對同類器物的原始稱呼與統一分類可以回查；同一批器物跨簡報、正式報告與圖錄出現時，以出土號和來源核對去重。
