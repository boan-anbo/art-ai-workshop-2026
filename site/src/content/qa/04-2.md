<strong>假設情境 · 英文：</strong>

<details class="original-question">
<summary>English · hypothetical scenario</summary>
<blockquote lang="en">Suppose a project needs object or document metadata. How could the schema support later queries, comparisons and revisions?</blockquote>
</details>

先用三個研究問題倒推欄位，再試填少量資料。精細的 metadata 應讓你能比較、查詢和返回來源。

器物、出土單位、報告及不同研究的判斷可以分開。尺寸留數值、單位和測量部位；年代保原說法及候選；缺值分清未報告、看不清與不適用。穩定 ID 和可變名稱分開，同一器物的不同定年不必壓成唯一答案。

[Getty AAT](https://www.getty.edu/research/tools/vocabularies/aat/) 可供詞彙對齊，[CIDOC CRM](https://cidoc-crm.org/) 可供概念與關係設計參考。先保留原詞和映射理由，再用小樣本實際查詢，按需要增加欄位或子表。Workshop 會把一個研究問題轉成可用的資料結構。

不要以為第一天就能設計出永遠不變的理想 schema。每進來一種新器物或新報告，就試着用現有欄位描述、實際查詢；放不下的地方，與 agent 用自然語言討論後修改模型，並遷移（migrate）舊資料，保留原值和修改依據。

Wikidata、CIDOC CRM 或 Getty 詞彙可以幫助思考，但先以<strong>自己的研究問題與材料</strong>為中心，不必為套標準而犧牲原材料的差異。等到要公開、交換或跨庫連接時，再明確設計對外映射，說清哪些概念能對齊、哪些不能。

例如「泥質灰陶繩紋折沿深腹罐」可按研究需要拆成陶質、陶色、紋飾、口沿與器類，同時留完整原描述。尺寸以部位分行；不同學者的定年各帶來源，不覆蓋前說。空值可再細分「未報告、殘損無法測、不適用、待核查」，避免把缺報誤算成零。
